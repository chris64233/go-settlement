# go-settlement

开发环境：Go 1.23.0。

银行转账退汇处理：已结算成功的转账仍可能因账户关闭等原因被银行退回，
本模块在保留原结算结果的前提下受理退汇、维护业务方余额并生成资金台账。

## 核心能力

- 转账生命周期：`CreateTransfer` 创建指令（PENDING），`ConfirmTransferSuccess`
  确认成功并扣减可用余额；成功状态与银行成功回执号一旦写入不可变，
  退汇不会把原转账改回失败，也不会删除原成功回执。
- 退汇受理：`SubmitReturn` 关联原银行指令，保存银行退汇号、退回金额、币种、
  原因与回执时间。仅当原指令成功且币种匹配时受理；一笔转账允许分多次退回，
  累计退回金额不得超过原转账金额。每次确认增加业务方可用余额并生成独立台账。
- 幂等与冲突：银行退汇号全局唯一。相同内容重复提交返回首次结果（幂等）；
  原指令、金额或币种任一变化返回 `ErrReturnConflict`。
- 冲正：错误退汇通过 `ReverseReturn` 独立冲正扣回，冲正号同样幂等，
  累计冲正不能超过对应退汇已入账金额；冲正后相应额度恢复为可退剩余金额。
- 并发安全：所有余额与台账变更在同一把互斥锁内完成。退汇确认、账户冻结
  （`Freeze`/`Unfreeze`）与提现（`Withdraw`）并发时，余额变化与退汇台账
  在同一结果中生效，任何失败都不会只完成一边，也不会造成超额入账。
- 查询：`GetTransferDetail` 返回原转账、全部退汇、冲正关联、资金台账
  与当前可退剩余金额；`GetAccount` 返回可用/冻结余额快照。

## 运行测试

    go test ./... -count=1 -race

测试覆盖：部分退回、并发超额拦截、重复回执幂等与冲突、冲正及其上限、
退汇/冻结/提现并发原子性。
