# go-settlement

开发环境：Go 1.23.0。

运行测试：

    go test ./...

## 银行暂收款认领

无法自动找到归属的银行来账先进入暂收账户，由运营人员发起认领，
可将一笔资金按实际用途拆分到多个收款对象。实现见 `receipt.go`，
金额一律使用最小货币单位（整数）表示。

### 来账导入

`ImportReceipt` 保存银行流水号、付款方、币种、金额、到账时间和原始摘要。
银行流水号全局唯一：完全相同的来账重复导入返回原结果（幂等）；
流水号相同但金额、币种或付款方不同则返回 `ErrConflict` 冲突。

### 认领

`SubmitClaim` 固定来账版本（`expectedVersion`），包含目标收款对象及各自金额。
一笔来账可分多次认领，但累计已入账金额与处理中金额之和不能超过来账金额。
一份申请中的多项分配要么全部成功，要么全部不生效；校验失败的申请以
`failed` 状态保留原因，但不生成资金台账。

资金变化：认领成功（pending）即占用相应暂收余额，`ConfirmClaim` 确认后
按每条分配生成 `claim_out` 台账（暂收 -> 收款对象），余额保持被占用状态。

### 并发与版本

所有变更操作（认领、确认、撤回、冲正）都携带来账版本号，采用乐观并发控制：
版本不匹配返回 `ErrVersionConflict`，旧版本申请不得覆盖较新的剩余金额；
存储层使用互斥锁串行化变更，保证多操作员并发认领同一来账不会超额分配。

### 撤回

`WithdrawClaim` 仅允许撤回处理中（pending）的认领，撤回后释放占用的
暂收余额，余额立即可被新的认领使用；已确认的认领不得撤回、删除或改写。

### 冲正

已确认的认领发现归属错误时，通过 `ReverseClaim` 生成独立冲正记录，
按冲正金额恢复暂收余额（生成 `reversal_in` 台账，收款对象 -> 暂收），
恢复后的余额可由新的认领重新处理。冲正金额不能超过该认领剩余可冲正金额；
冲正携带幂等键，重复冲正返回原记录，不会重复加回余额。

### 查询

- `Balance`：来账剩余暂收余额。
- `ClaimProgress`：认领进度（含失败申请及原因）。
- `Allocations`：有效分配明细。
- `Reversals`：冲正记录。
- `Ledger`：按银行流水号查询资金去向，每条台账均可追溯原银行流水。
