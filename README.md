# go-settlement

开发环境：Go 1.23.0。

运行测试：

    go test ./...

## 结算付款预扣税

### 核心概念

- **税务身份（TaxIdentity）**：记录收款方所属地区、身份类型与有效期（起止日均含当日）。同一收款方可登记多个版本。
- **税率规则（TaxRateRule）**：按地区、收入类型、金额区间 `[MinAmount, MaxAmount)`（`MaxAmount` 为 0 表示不设上限）与生效时间发布，税率以万分比（bps）表示。
- **结算受理（AcceptSettlement）**：为每条明细固定收款方身份版本、收入类型与交易发生日；交易发生日无有效身份时报错，不会套用其他身份。
- **付款确认（ConfirmPayment）**：同一结算只生成一份有效扣税结果与凭证编号（`WHT-XXXXXX`），重复确认幂等返回原结果。
- **更正（Correction）**：身份更正或税率更新不覆盖历史结果，通过独立更正记录（补扣 `additional` / 退回 `refund`）调整差额，并关联原凭证编号。

### 税额计算依据

1. 金额以“分”（`Money`，int64）为最小单位，避免浮点误差。
2. 每条明细按交易发生日匹配：有效身份（版本最高者优先）→ 身份地区 + 收入类型 + 毛额所在区间 + 当日生效的税率规则。
3. 多条明细共享一个付款时，按（身份版本, 规则版本, 税率）分组：先对分组毛额合计按 `round(gross × rateBps / 10000)` 四舍五入得到分组目标税额；组内各行先向下取整，再按精确税额余数从大到小各补 1 分，余数相同按 `LineID` 字典序分配（稳定规则）。
4. 每行恒有 `Tax + Net = Gross`，且各行税额之和等于分组级取整结果，不产生合计偏差。
5. 凭证（`GetVoucher`）中每条明细携带采用的身份 ID/版本与规则 ID/版本，可追溯计算依据。

### API 一览

| 方法 | 说明 |
| --- | --- |
| `RegisterIdentity` | 身份登记 |
| `PublishRateRule` | 税率发布 |
| `AcceptSettlement` | 结算受理（固定身份版本/收入类型/交易日） |
| `TrialCalculate` | 税额试算（不产生凭证、不改状态） |
| `ConfirmPayment` | 付款确认（幂等，生成唯一凭证） |
| `GetVoucher` | 凭证查询 |
| `AddCorrection` / `ListCorrections` | 更正登记与查询 |
