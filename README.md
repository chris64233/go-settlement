# go-settlement

开发环境：Go 1.23.0。

运行测试：

    go test ./...

## 预扣税处理

本模块实现结算付款的预扣税（withholding tax）处理：按收款方税务身份与交易发生日
适用规则计算应扣税额，并生成可追溯的完税凭证。

### 核心概念

- **税务身份**（`identity.go`）：记录收款方所属地区、身份类型与有效期，
  有效期为左闭右开区间 `[ValidFrom, ValidTo)`。每次登记生成一个不可变版本号。
- **税率规则**（`rule.go`）：按地区、收入类型、金额区间（超额累进的分段，
  区间为 `[Lower, Upper)`，`Upper=0` 表示不封顶）与生效时间
  `[EffectiveFrom, EffectiveTo)` 发布，每次发布生成一个不可变版本号。
- **结算受理**（`AcceptSettlement`）：受理时固定收款方身份版本、收入类型与
  交易发生日。交易发生日当天无有效身份时直接报错，不会自行套用其他身份。
- **付款确认**（`ConfirmPayment`）：计算应扣税额与实付金额并生成唯一凭证编号
  `WHT-<结算编号>`。同一结算重复确认返回同一份结果，身份更正或税率更新均不会
  覆盖历史结果；确需修改时通过 `AddCorrection` 追加独立的补扣/退回记录。
- **税额试算**（`SimulateTax`）：按受理时固定的身份与交易发生日计算，不落库、
  不生成凭证。

### 税额计算依据

1. **身份与规则定位**：以受理时固定的身份版本确定地区，以交易发生日落在身份
   有效期与规则生效期内（均为左闭右开）为条件选取版本；同一日期多个规则版本
   重叠时取版本号最高者。
2. **累进税额**：对每条明细毛额按分段区间做超额累进，税率为万分比
   （`RateBps`，10000 = 100%）。金额单位为分，精确税额以 1/10000 分为单位
   累积，避免中途舍入。
3. **舍入与分摊**：先对全部明细的合计精确税额做四舍五入（half up）得到目标
   总税额，再按最大余数法分摊到各明细——每行先取精确税额的整数部分，剩余
   差额按小数余数降序、明细编号升序（稳定规则）逐分补齐。保证
   `Σ税额 + Σ实付 = Σ毛额`，多明细共享一个付款时不产生合计偏差。
4. **可追溯凭证**：凭证记录采用的身份版本、地区、身份类型、税率版本、收入
   类型、交易发生日及逐明细的税额与实付，生成后不可变；更正记录独立追加，
   可查询完整历史。

### 主要接口

| 方法 | 说明 |
| --- | --- |
| `RegisterIdentity` | 身份登记，返回版本号 |
| `PublishRule` | 税率发布，返回版本号 |
| `AcceptSettlement` | 结算受理，固定身份版本/收入类型/交易日 |
| `SimulateTax` | 税额试算（不落库） |
| `ConfirmPayment` | 付款确认，生成唯一凭证（幂等） |
| `GetVoucher` | 完税凭证查询 |
| `AddCorrection` / `ListCorrections` | 更正追加与查询 |
