# go-settlement

开发环境：Go 1.23.0。

运行测试：

    go test ./...

## 结算日历与批次排期

核心代码位于 `calendar.go`（日历版本与价值日计算）和 `service.go`（批次、调整与并发控制）。

### 价值日规则

批次价值日由命中的日历版本（币种 + 渠道确定适用范围）按以下规则计算：

1. 受理时间不晚于当日截点（`Cutoff`），候选日为受理当日；超过截点，候选日顺延一天。
2. 候选日若不是工作日（周末或日历中的节假日），顺延到下一个工作日。
3. 批次创建时记录命中的日历版本号、受理时间与价值日；`ExplainBatch` 可返回完整推导过程。

### 日历调整

- 日历只能以新版本调整，已生效的版本与调整记录不可删除。
- `PreviewAdjustment` 先生成影响清单：列出所有会改变价值日的未提交批次及其旧/新价值日。
- `ConfirmAdjustment` 确认时重新校验影响范围；若预览后范围发生变化（例如批次被送出），旧清单作废，需重新预览。
- 确认后未送银行的受影响批次在同一把锁内一次性迁移；已送银行的批次始终保留原价值日。
- 相同调整号 + 相同内容重放返回原结果；同号不同内容返回冲突。

### 并发与测试

所有状态变更（日历确认、批次送出、批次创建）共用一把互斥锁，保证原子性。
测试覆盖截点边界、节假日/周末顺延、送出竞态（`-race`）、重复调整幂等与清单失效等场景。
