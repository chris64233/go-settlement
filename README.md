# go-settlement

开发环境：Go 1.23.0。

运行测试：

    go test ./...

## 功能

结算转账被银行拒绝后的修复能力。运营人员可修正收款信息并重新发送，
原指令与银行回执完整保留、不可修改。

### 核心能力

- **指令创建与回执登记**：`CreateInstruction` 创建转账指令并占用资金预留；
  `RegisterReceipt` 登记银行成功/拒绝回执，回执永久保留。
- **修复申请**：`RequestRepair` 仅允许"收到明确拒绝回执且尚未成功"的转账发起。
  修复申请固定原指令、拒绝原因、原收款信息摘要、新收款信息和原指令版本，
  不修改旧指令。
- **修复确认**：`ConfirmRepair` 原子地生成关联新指令、迁移原资金预留、
  记录修复关系。新指令的金额、币种、资金归属与原指令一致，仅收款信息变更；
  预留直接转移，不存在先释放再重复占用的中间态。任一步失败不产生副作用，
  原拒绝状态仍可继续处理。
- **竞态处理**：原指令成功回执、修复确认、取消同时到达时只有一条指令获得
  最终成功。原指令先成功则修复作废；修复确认后收到原指令迟到成功回执时，
  原指令标记为人工处理（`MANUAL_REVIEW`）并记录异常，不重复记账。
- **幂等**：银行请求号、修复号、回执号均为幂等键；同号同内容返回原结果，
  同号不同内容返回冲突（`ErrConflict`）。
- **查询**：`GetInstructionView` 返回原指令、全部修复版本、银行回执、
  资金预留去向（含转移轨迹）和需要人工处理的异常；`Ledger` 返回记账记录，
  `Exceptions` 返回人工处理异常。

### 代码结构

- `types.go`：指令、修复、回执、资金预留、记账、异常等领域模型。
- `service.go`：内存实现的服务，全部状态迁移在单锁内原子完成。
- `service_test.go`：覆盖创建幂等、修复校验、确认原子性、预留转移、
  竞态（原指令先成功 / 迟到成功回执）、回执幂等、取消与查询视图的测试。
