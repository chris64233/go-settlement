开发环境：Go 1.23.0。

运行测试：

    go test ./...

## 结算日历与批次排期

### 价值日规则

批次的价值日（value date）由**币种 + 渠道**对应的日历版本、**每日截点**和**受理时间**共同决定：

1. 受理日为工作日且受理时间**不晚于**当日截点（恰好等于截点视为不晚于），价值日为受理日当天。
2. 受理时间晚于截点，或受理日为非工作日，价值日顺延到**下一个工作日**。
3. 工作日默认按周一到周五判定；日历中的 `Holidays` 将指定日期标记为非工作日，`ExtraWorkday` 将指定日期（如调休周末）标记为工作日。

批次创建时记录命中的日历版本、受理时间和价值日；`ExplainBatchValueDate` 可逐步解释日期是如何得出的。

### 日历临时调整

1. `PrepareAdjustment` 生成影响清单（`ImpactReport`），列出会改变价值日的**未提交**批次及其旧日期、新日期，以及调整前后的日历差异。
2. `ConfirmAdjustment` 确认时重新校验基准日历版本和影响范围；若期间新建了受影响批次或日历版本已变化，旧清单作废（`ErrReportStale`），需重新生成。
3. 确认后新日历版本生效，所有受影响的未提交批次**一次性**迁移；**已送银行的批次永远保留原价值日**，不参与重新排期。
4. 相同调整号 + 相同内容重放返回原结果（幂等）；日期、范围或规则变化返回 `ErrAdjustmentConflict`。
5. 已生效的调整不得删除（`ErrAdjustmentEffective`），只能通过新的调整版本恢复或再次调整。

### 并发语义

所有服务方法持有同一把互斥锁：日历确认、批次送银行、新批次创建并发时，操作按串行顺序生效——先送出的批次保留原价值日（随后的确认因影响范围变化被拒绝），先确认的批次按新价值日迁移后再送出。
