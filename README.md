# go-settlement

开发环境：Go 1.23.0。

运行测试：

    go test ./...

## 功能

参与方之间的结算限额控制，在接受资金指令时计算双方当日累计风险，
并发提交不会绕过单边或双边限额。

- **限额规则**（`limit.go`）：按参与方、对手方、币种和生效时间维护，
  可设置单笔上限、双边净敞口上限和单方总敞口上限（0 表示不启用）。
  每次 `PublishRule` 形成新的版本号；已受理的指令保留当时采用的版本。
- **指令受理**（`instruction.go`）：`Accept` 固定付款方、收款方、金额、
  价值日和限额版本，并在同一把互斥锁（同一持久化边界）内完成限额校验
  与双方占用增加。任一层限额不足时整笔拒绝（`LimitExceededError`），
  不会只增加其中一方的占用。`RequestID` 保证受理幂等。
- **状态流转**：`Complete` 将占用转为已用额度（仍计入当日累计）；
  `Cancel` / `Fail` 按原占用记录释放额度。已完成的指令不可再取消
  （`ErrInvalidState`），迟到取消不会释放其他指令后来取得的额度。
- **占用查询**（`occupancy.go`）：`QueryOccupancy` 按参与方、对手方、
  币种和价值日返回持有/已用金额、单方总敞口、双边净头寸及逐笔明细。

## 测试

`settlement_test.go` 覆盖：限额版本切换、多层限额冲突（拒绝后无部分占用）、
并发争用剩余额度不超限（`-race`）、重复请求幂等、迟到取消与失败释放。
