# go-settlement

开发环境：Go 1.18+。

运行测试：

    go test ./...

## 银行暂收款认领

无法自动找到归属的银行来账先进入暂收账户，由运营人员认领并拆分到多个收款对象。
实现见 `settlement.go`，金额一律使用最小货币单位（`int64`）。

### 来账导入

- `ImportReceipt` 保存银行流水号、付款方、币种、金额、到账时间和原始摘要。
- 银行流水号全局唯一：重复导入且金额、币种、付款方一致时返回原记录（幂等）；
  任一关键字段变化时返回 `ErrReceiptConflict`。

### 认领与资金变化

- `SubmitClaim` 固定提交时的来账版本，一份申请可包含多个收款对象的分配；
  提交后对应金额计入「处理中」，`可用 = 总额 - 已入账 - 处理中`，累计不得超过来账金额。
- `ConfirmClaim` 将申请的全部分配一次性入账（全部成功或全部不生效）：
  处理中金额转为已入账金额，并为每项分配生成资金台账。
  若申请锁定的版本已被更新的确认、撤回或认领推进，则确认失败，
  申请置为 `FAILED` 并保留原因，占用金额释放，不生成台账。
- `WithdrawClaim` 撤回处理中的申请：处理中金额释放回可用余额，不产生台账。

### 冲正

- 已确认的认领不得删除或改写；归属错误时通过 `Reverse` 生成独立冲正记录，
  按冲正金额减少已入账、恢复暂收余额，并写入负向台账。
- 冲正金额不得超过该认领剩余可冲正金额；相同冲正号重复提交返回原记录，
  不会重复加回余额。冲正后恢复的余额可由新的认领再次处理。

### 查询

- `GetBalance`：来账余额与认领进度（总额 / 已入账 / 处理中 / 可用 / 版本）。
- `GetClaim`、`ListClaims`：认领申请及分配明细。
- `ListReversals`：冲正记录。
- `ListLedger`：资金去向台账，每条记录均携带银行流水号，可追溯到原始终来账。
