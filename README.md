# go-settlement

开发环境：Go 1.23.0。

运行测试：

    go test ./...

## 结算指令排队服务

本仓库实现一个受可用资金约束的结算指令排队服务（包 `settlement`）。

### 指令与顺序

- 指令记录付款账户、金额、币种、价值日、优先级和最晚处理时间（`RegisterCommand`）。
- 受理后按 **优先级（降序）→ 受理序号（升序）→ 外部指令号（升序）** 形成稳定顺序。
- 幂等受理：同一外部指令号提交相同内容返回原结果；关键内容（账户、金额、币种、
  价值日、优先级、截止时间、越过标记）变化时返回 `ConflictError`。
- 金额使用 `Amount`（基于 `big.Rat`）精确表示，JSON 以字符串编码，无浮点误差。

### 释放扫描

- 每次 `Scan` 开始时固定队列版本与账户余额快照，基于快照计算释放计划。
- 余额（账户+币种）能够覆盖指令金额时才允许释放，释放即扣减余额。
- 遇到无法覆盖的指令时按策略处理：
  - `PolicyStopOnInsufficient`（默认）：停止本次扫描，后续指令全部等待；
  - `PolicyAllowMarkedOvertake`：只放行明确标记 `AllowOvertake` 的后续指令，
    未标记的指令即使余额足够也不得越过资金缺口。
- 超过最晚处理时间的指令转为 `EXPIRED`，不再阻塞队列。
- 人工冻结（`SetFrozen`）期间该账户+币种的余额不参与释放。

### 并发与一致性

- 任何改变队列或余额的操作都会递增队列版本；扫描提交时校验版本，
  版本变化则返回 `ErrVersionConflict`，队列顺序与未释放指令保持不变。
- 入账、冻结与多个扫描并发时，同一笔余额不会被重复使用，
  每条指令最多从等待进入释放状态一次。

### 查询接口

- `Register`：指令登记（幂等）。
- `ApplyBalanceChange` / `SetFrozen` / `Balance`：余额变动与冻结。
- `Scan`：释放扫描，返回释放与跳过明细。
- `Queue`：队列稳定顺序视图。
- `Explain`：单条指令的等待原因或释放依据（扫描批次、释放前后余额、队列版本）。
